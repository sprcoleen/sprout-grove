Every AI tool or internal app built at Sprout must be registered in Grove and pass through a lightweight governance process before going live. This guide walks you through each step — from idea to production.

⚠️ Why Grove governance matters — Sprout employees can build and ship internal tools using Claude, ChatGPT, and other AI platforms — many of which can access internal databases, handle employee PII, or send data to external AI providers. Without a governance process these tools may violate the PH Data Privacy Act, TH PDPA, or Sprout's internal data policies. Grove is the safeguard.

How to Create & Manage Your AI Project
1
Register your project in Grove ALL TIERS
Log into grove.sprout.solutions with your Sprout email. Go to the Garden tab and click Add Plant. Fill in:
  • Project name — clear, descriptive
  • Description — what it does and the problem it solves
  • Your team & target department
  • AI tools used (Claude, ChatGPT, Copilot, etc.)
  • Project link — prototype URL, internal tool, or live product (optional at first)
💡 Country is set automatically from your email domain — @sprout.ph → PH, @sproutsolutions.io → TH. It cannot be changed.
2
Complete Security & Data Classification MANDATORY GATE
Open your project, click the Technical tab, and answer all 5 security questions. This is required before your project can advance past Sprout stage. You'll also fill in:
  • Does it have a backend or server-side logic?
  • Who are the target users — internal only, external, or both?
  • Hosting platform, database & data sources, auth method
3
Tier is auto-assigned AUTO-COMPUTED
Grove computes your Tier (1 / 2 / 3) automatically based on your answers about backend and target users. Tier determines how much review is needed before going live. See the Tier section below.
ℹ️ Unclassified projects are blocked from all stage changes — complete classification first.
4
Advance through stages as you build GATES ENFORCED
Use the stage selector on your project page to move from Sprout → Growing → Blooming → Thriving as your work progresses. Gates are enforced at Growing → Blooming and Blooming → Thriving for Tier 2 and Tier 3 projects.
💡 Before creating Jira tickets for the Groundskeeper team (Raffy, Coleen, Nikki, Blaise), IS / Execom approval must be secured at the Growing stage. See IS / Execom Gate.
5
Submit for Release Manager review (Tier 2 & 3) TIER 2 & 3 ONLY
If your project is Tier 2 or 3, click Submit for Release Review before each gate transition. The Release Manager (Belle Asis or Diane Litan) reviews your classification and approves, rejects, or requests changes. Tier 3 projects also get a Jira DevOps ticket created for Groundskeeper support.
6
Go live — reach Thriving 🌳 PRODUCTION
Once all gates are cleared your project reaches Thriving — fully deployed and part of Sprout's official AI portfolio. Tier 3 projects must also complete the policy compliance checklist before this final step.

IS / Execom Approval Gate
Before any Jira ticket is raised for the Groundskeepers (Raffy, Coleen, Nikki, Blaise) to begin go-live support work, approval from IS (Information Security department) or Execom (Executive Committee) must be in place. The Groundskeepers are your Project Support & DevOps team — IS and Execom are the approval bodies that sign off on the work.
Sprout Stage
Optional
IS / Execom approval is encouraged but not blocking at this stage. Teams should proactively seek approval early to avoid delays later.
💡 Best practice: secure approval during Sprout so Growing → Blooming is unblocked.
Growing Stage
Required
IS / Execom approval is mandatory before any ticket for Coleen, Blaise, Nikki, or Raffy can be created. Without it the project is blocked from advancing to Blooming.
🚦 Gate: advancing Growing → Blooming requires this approval on record.
Who gives approval? IS (Information Security department) or Execom (Executive Committee) — these are the approval bodies, separate from the Groundskeeper team. Approval must be documented before any go-live ticket is raised for Raffy, Coleen, Nikki, or Blaise. This requirement applies regardless of the project's Tier.

Security & Data Classification Questions
These 5 questions appear in the Technical tab of your project and must be answered before your project can advance past Sprout. Answering YES to Q2 or Q4 automatically escalates the project to Tier 3.
Q1
Does this tool require user login / authentication?
If YES: Access control layer is required
Q2
Does it access external APIs or third-party services?
If YES: Data egress risk — review required
→ Tier 3
Q3
Does it handle or display sensitive employee / client data?
If YES: PDPA / Data Privacy Act compliance required
Q4
Does it send data to an external AI service? (OpenAI, Claude, Gemini, Azure AI, etc.)
If YES: Data-sharing policy review required
→ Tier 3
Q5
Does it store user inputs in a database?
If YES: Data retention policy applies
⚠ Auto-escalation rule: If a project requires authentication AND handles sensitive data, it is automatically classified as Tier 3 regardless of other answers. Coordinate with Belle or Coleen before shipping.

📋
Go-Live Compliance Checklist
Tier 3 projects must complete this checklist before reaching Thriving. Tier 2 projects should review these items as best practice.
  • Data Minimization — only collecting what is strictly necessary for the tool's purpose
  • Access Control — access is restricted to authorized users only
  • No hardcoded credentials or API keys in source code
  • No PII stored in application logs
  • Compliant with PH Data Privacy Act and / or TH PDPA (as applicable)
  • Reviewed by at least one person who is not the builder
  • DevOps infrastructure confirmed — GitHub repo, hosting platform, database
  • IS / Execom approval on record
  • Release Manager has reviewed and signed off in Grove
