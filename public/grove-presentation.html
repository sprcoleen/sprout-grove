About

One home for every
AI initiative at Sprout

Before Grove, AI projects lived in scattered spreadsheets, Slack threads, and tribal knowledge. There was no easy way to see what was being built, where it stood, or who needed help to ship.

Grove changes that. It's a single, living registry where any Sprout employee can document an AI project, track it from prototype to production, get infrastructure support, and know exactly what's required before going live.

Admins and Release Managers have full visibility — audit tools, release review gates, and classification checks — so nothing ships without the right sign-offs.

How it works

From wishlist to live product

01
Submit a Seed
Any Sprout employee spots an AI opportunity and posts it to the Wishlist. Others can upvote to signal interest.
Anyone can do this
02
Claim & Start Building
A Gardener claims an unclaimed Seed and starts building. The Seed becomes a Project, starting at Sprout stage.
Gardeners
03
Classify Your Project
Answer two questions — does it have a backend? Who are the users? Grove auto-assigns a Tier (1, 2, or 3) that determines hosting and review requirements.
Required
04
Request Setup Support
Need a GitHub repo, hosting, or a database? One click creates a Jira ticket routed to the right Groundskeeper for your tier.
Groundskeepers
05
Pass Release Review
Tier 2 and 3 projects require a Release Manager sign-off before advancing to Blooming or Thriving. Submit, wait for approval or feedback.
Release Managers
06
Go Live & Keep Growing
Project advances to Blooming or Thriving. The Momentum feed logs every milestone so the whole company can see what's shipping.
Visible to all
Features

Everything a growing AI project needs

🌱
Seed Wishlist
A shared backlog of AI ideas. Submit, upvote, and claim — so good ideas don't get lost in Slack.
🌿
Garden Board
Kanban-style view of all projects across every stage. Drag to advance, filter by department, stage, or country.
📐
Tier Classification
Two questions auto-assign a tier. The tier determines hosting, which Groundskeeper owns setup, and what reviews are required.
✅
Release Review Gate
Tier 2 and 3 projects must pass a Release Manager review before going live. Approved, pending, or rejected — fully tracked.
🛠️
Setup Support Tickets
One-click Jira ticket creation for GitHub repo, hosting platform, and database setup — routed to the right Groundskeeper automatically.
📡
Momentum Feed
A real-time activity log of every stage advance, note, and milestone — so the company always knows what's shipping.
Classification

Three tiers, two questions

Tier is computed automatically from two fields. It determines hosting requirements, Groundskeeper assignment, and which security reviews apply.

Q1 — Does the project have a backend, database, or server-side logic? + Q2 — Who are the target users: internal, external, or both?
Tier 1
Static / Internal
No backend · Internal users only
Hosted on Markup
Uploaded directly by the project owner. No infrastructure setup required. No release review needed.
Tier 2
Internal App
Has backend OR external/both users
Sprout Vercel / Azure
Requires IS/ExCom approval. Groundskeeper: Raphael Enriquez. Release review required before Blooming and Thriving.
Tier 3
External-Facing
Has backend AND external/both users
Sprout Vercel / Azure
Requires IS/ExCom approval. Groundskeeper: Coleen Bartido. Full security sign-off required. DPO review if sensitive data is sent to external AI.
